# Grill: 模型连接检测简化
Date: 2026-10-08

## Intent
模型配置详情页只验证聊天模型能否通过当前连接返回普通聊天响应。连接成功的模型即可进入聊天与默认模型选择，无需工具能力检测或手动填写上下文容量。

## Constraints
- 保留连接地址、Key 更新后的重新验证与检测期间连接变更保护。
- 不覆盖工作区已有的未提交改动。
- 容量未知时允许发送临时文件，由模型服务商判断是否超限；已有容量值仍可用于预先限制。

## Key decisions
- Decision: 测试只发送一次普通聊天请求并记录 chat 已验证。Reason: 用户只要求检测能否连接。Alternative considered: 继续三阶段工具能力检测。
- Decision: 连接验证通过即可进入聊天模型列表和设为默认。Reason: 避免前端显示成功但后端仍拒绝。Alternative considered: 只改界面文案。
- Decision: 新检测的模型不声明工具能力，运行时提供普通聊天；旧模型已验证的工具能力继续使用。Reason: 未验证的工具协议不能作为新模型可用条件，同时保持旧模型行为。

## Surfaced assumptions
- “能否连接”指一次有效的普通聊天响应，而非只访问模型列表或检查 HTTP 可达性。
- 既有模型的容量数据库字段和 API 可保留为兼容数据，但详情页不要求填写。

## Open questions
- 用户尚未明确要求所有模型都尝试工具调用；当前采用只对已验证工具的旧模型提供工具的行为。
