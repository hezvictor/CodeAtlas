# CodeAtlas Phase 2 浏览器测试流程

## 测试环境
- 前端：`http://localhost:3000`
- 后端：`http://localhost:8000`
- 浏览器：Chromium，通过 agent-browser 执行
- 每轮使用独立测试账号，避免数据互相污染

## A. 可用性与导航
1. 打开首页，确认页面返回、品牌和导航可见。
2. 依次进入首页、聊天、题库、知识库，确认顶部导航始终固定在顶部。
3. 缩小到移动视口，确认页面无横向溢出，导航和内容仍可操作。

## B. 注册
1. 使用合法邮箱、昵称和 8 位以上密码注册，预期成功进入聊天页并保存登录状态。
2. 使用无效邮箱，预期显示输入校验，不发送成功请求。
3. 使用少于 8 位密码，预期显示输入校验。
4. 使用已注册邮箱，预期显示友好的注册失败提示。

## C. 登录
1. 使用正确账号密码，预期进入聊天页。
2. 使用错误密码，预期留在登录页并显示“邮箱或密码不正确”。
3. 使用不存在邮箱，预期显示同样的友好提示，不暴露后端堆栈。
4. 后端不可用时提交，预期显示全局网络错误通知，不出现白屏。
5. 刷新登录页，确认页面仍可正常加载。

## D. 会话与聊天
1. 登录后新建会话，预期左侧出现会话。
2. 发送消息，预期用户消息立即出现，助手消息以流式内容更新。
3. 首条消息发送后，预期会话标题自动改为消息摘要。
4. 双击会话标题，修改名称，按 Enter 和失焦分别验证保存。
5. 切换普通模式，预期保持普通模式。
6. 点击 ACM 分析/解题模式，预期显示占位状态，不伪装为已实现。
7. 用户和助手消息点击复制，预期剪贴板内容与消息一致。
8. 刷新页面并重新打开会话，预期已保存消息仍存在。
9. 无活动会话时发送，预期按钮不可用，不产生异常。

## E. 占位页面与全局异常
1. 打开题库和知识库，确认显示 Phase 3/4 占位说明。
2. 访问不存在路由，确认 Next.js 404 页面可见。
3. 模拟未处理异常/网络失败，确认全局通知出现且可关闭。
4. 检查浏览器控制台无阻断应用使用的运行时错误。
