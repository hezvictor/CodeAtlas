## 真实 API 与界面验收

- Markdown 文档实际生成 19 个文本块，进度依次记录 `0/19 → 10/19 → 19/19`，完整提交后才启用索引。修正 text-embedding-v3/v4 批次上限，原配置为 16 时也按最多 10 条发送。
- 同名预检、相同内容跳过、不同内容明确选择、独立文档时间戳命名均通过。MinIO 对象末尾文件名与页面版本文件名一致，中文保持完整。
- 空的新版本处理失败时，旧索引与旧原文件下载仍可用。有效的新版本成功切换后，原旧版及失败的待替换版对象、提取文本和向量均清理，保留简要记录。
- 重新索引使用独立任务 generation。等待 Embedding 配置时原件已保存但索引未启用；配置验证成功后原任务自动恢复并完成。
- 新 PDF 上传拒绝。已有完整 PDF 索引的兼容性由原解析与检索策略及回归测试覆盖，未增加 OCR 或多模态解析。
- 浏览器批量选两个文件，保存完成后显示“全部文件已保存或跳过，可以安全离开”。为确定后台独立性，保存时暂停 worker，然后切至题库并恢复 worker；导航提示从“处理中 2”变成“完成 2”，返回知识库后两个文档均可检索，已观察的完成提醒消失。
- 文档详情显示处理阶段、当前可检索版本、当前下载、预览和简要版本记录。空列表隐藏统计，并显示支持格式与大小限制。
- 浏览器删除确认明确说明原文件、文本和向量索引会清理且不可恢复。删除后的详情刷新竞态已补回归测试，404 返回列表，不显示误导的全局失败提示。
- 在最终构建上另用一个隔离账号复核详情删除，确认返回空列表且没有错误通知；该文档原件及文本块/向量清零，账号随后删除。
- 浏览器对一个测试文档执行删除，其余五个通过 API 删除。最终核对六个文档的清理状态完成，原件对象为 0、文本块/向量为 0、当前索引指针均为空。

400 永久失败、429/超时自动重试、删除中止写入、重建失败保留旧 generation、清理失败后再次执行、历史引用保留等异常路径，由真实 PostgreSQL 集成测试覆盖。迁移会同步将不完整旧索引及其残留的已完成任务标记为失败；界面还要求存在启用版本才能显示“可检索”和 100%。未保存文件离开时中止传输、传输 100% 仍需等待服务端保存确认，由 XHR 边界回归验证。

六个正式容器均运行：frontend、backend、worker、postgres、redis、minio；具有健康检查的服务均 healthy。访问前端 `http://localhost:3000`，API 文档 `http://localhost:8000/docs`，MinIO 控制台 `http://localhost:9001`。

数据库逻辑备份保存在忽略提交的 `.build-context/verification-backup/before-acceptance.sql`。这是新环境初次迁移后的、业务验收前的快照；不能用于恢复用户此前已经删除的数据卷。最终服务重建时在该备份之后再次运行 `alembic upgrade head`。
