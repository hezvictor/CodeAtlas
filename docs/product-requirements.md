# CodeAtlas：ACM 私人知识库 AI 助教平台功能需求文档

**版本**：0.1（需求基线）  
**日期**：2026-09-07  
**状态**：初版开发基线

## 1. 产品定位

面向 ACM/OI 竞赛学习者的私人知识库 AI 助教。用户可以在统一聊天界面中提问算法问题、上传当前会话相关资料，并通过个人题库、笔记、题解和代码获得带引用的回答。平台重点帮助用户理解题目、建立解题思路和复盘，而不是替代在线评测系统。

## 2. 用户与目标

### 主要用户

- 正在学习算法竞赛的学生或个人开发者。
- 具备基础编程能力，希望系统分析题目和沉淀知识的用户。

### 核心目标

- 缩短从读题到形成正确解题思路的时间。
- 将零散的题解、模板、笔记和课程资料变成可检索的私人知识库。
- 通过分析模式避免过早看到代码，通过解题模式获得规范的竞赛代码。
- 每个重要回答都能追溯到上传文档或题库内容。

## 3. MVP 功能范围

### 3.1 首页与导航

- 顶部导航：首页、聊天、题库、知识库；为后续训练、比赛、作业、讨论和评测记录预留入口。
- 未登录用户可浏览产品介绍和登录/注册入口。
- 登录后显示用户菜单、头像和退出操作。
- 页面保持简洁、信息密度适中，聊天页参考主流 AI 聊天产品的左右布局。

### 3.2 用户系统

- 邮箱和密码注册、登录、退出。
- 登录态保持与过期处理。
- 查看和修改昵称、头像等基础资料。
- 修改密码。
- 个人数据按用户隔离；MVP 不开放公开或小组共享权限。

### 3.3 AI 聊天

- 创建、重命名、删除和切换会话。
- 按最近使用时间展示会话列表，并支持会话搜索（可作为 MVP 后半段）。
- 支持 Markdown、代码高亮、复制代码、重新生成和编辑后重试。重新生成或编辑后重试时，从目标消息开始截断后续消息，再基于截断后的历史生成新回答。
- 支持上传当前会话文件，并在回答中引用这些文件。
- 使用流式响应显示回答过程和生成状态。
- 支持停止生成；支持从最近一次已持久化状态继续执行。
- 记录用户消息、助手消息、模型、耗时、状态和引用来源；不记录模型 token 用量统计。
- 将回答中的“思考过程”限定为可解释的解题步骤、分析摘要和工具状态，不要求暴露模型内部隐式推理链。

### 3.4 ACM 模式

- 普通模式与 ACM 模式可切换。
- ACM 分析模式：提取输入输出、约束条件、题目目标、样例规律、题型、算法候选、正确性思路及复杂度；默认不输出完整代码。
- ACM 解题模式：先确认用户期望语言，再输出适合 ACM/OI 的完整代码、注释、输入输出处理、算法说明和复杂度。
- 支持 C++、Java、Python 三种语言作为首批选项。
- 对不完整题面、约束缺失或题意歧义给出澄清问题，不直接臆造结论。
- 支持 `@题目名` 引用私人题库中的题目；输入 `@` 时展示可选择的题目列表。
- 引用题目后，回答应优先使用该题目的题面、用户笔记和相关题解，并明确引用来源。

### 3.5 私人知识库

- 分组：算法模板、个人笔记、题解、比赛总结、错题、课程资料。
- 文件类型：Markdown、PDF、Word、TXT、C++/Java/Python 源码和网页内容。
- 上传、预览、删除、重新索引和失败重试。
- 展示上传进度、解析状态、分块状态、向量化状态和失败原因。
- 保留文档基础版本信息，MVP 支持重新上传形成新版本；复杂差异对比后续实现。
- 检索结果保存文档、页码、章节、段落或代码行号等定位信息。
- 文档默认仅当前用户可访问。

### 3.6 引用与检索

- 回答显示引用来源，区分“当前会话文件”和“私人知识库”。
- 引用支持跳转到文档预览位置。
- 检索优先采用混合检索：关键词匹配 + 向量相似度；结合 rerank 能力可后置。
- 召回不足时明确告知“知识库未找到足够依据”，避免伪造引用。

## 4. 后续版本

- 公开知识库、小组共享、只读/可编辑权限。
- OCR 题目截图识别。
- 训练计划、错题本自动整理、知识图谱和学习统计。
- 在线 OJ、代码编译运行、提交评测、比赛系统、讨论区和排行榜。
- DeepSeek 等其他聊天模型接入，以及本地模型部署。

## 5. 关键验收标准

- 用户注册后能登录并创建独立会话。
- 上传支持格式的文件后，能看到解析/索引状态，并在聊天中获得带准确来源的回答。
- 流式回答可以被停止；停止后会话消息状态一致，刷新页面不会丢失已持久化内容。
- ACM 分析模式默认无完整代码；解题模式会先确认语言并返回可提交风格代码。
- 使用 `@` 可以从私人题库选择题目，并将题目内容作为限定上下文参与回答。
- 任意用户无法读取其他用户的会话、文件、向量和引用。

## 6. 非功能要求

- 个人/小规模部署，优先保证稳定性、可维护性和数据隔离。
- 普通 API 在本地服务内响应目标小于 500ms；模型首 token 和总耗时受第三方服务影响，需记录耗时指标。
- 所有模型密钥只从环境变量读取，不进入代码、文档、日志或 Git。
- 上传文件限制大小和 MIME 类型；解析任务异步执行，失败可重试。
- 对模型输出做基础安全过滤，并在提示词中防御文档提示注入。
