# 聊天会话管理与可靠知识库回答设计

**日期：** 2026-09-14  
**状态：** 待用户评审  
**适用范围：** CodeAtlas 聊天页、会话管理、私人知识库聊天集成

## 1. 目标

本次改动聚焦于聊天界面的会话生命周期、会话管理、流式回答可靠性、知识库选择与回答依据展示，以及知识库上传错误提示。

完成后应满足：

1. 点击“新建会话”只创建一个前端临时草稿，不写入数据库；用户发送第一条问题时才创建真实会话并保存消息。
2. 会话支持三个点菜单、重命名、置顶、单独删除、多选、批量置顶和批量删除。分享功能永久不实现，也不出现在界面或本次新增 API 中。
3. AI 生成任务独立于浏览器页面和 SSE 连接。刷新页面、关闭聊天页后重新打开、退出并重新登录，都能看到最终回答；只有用户点击“停止生成”才取消任务。
4. 后端进程持续运行时，重新进入正在生成的会话会先显示已生成的内容，再继续接收增量，最终显示完整答案。后端进程重启后的续生成不属于本次范围。
5. 知识库选择支持“不使用知识库”“使用所有知识库”“指定知识库分组”，默认不使用；检索严格按当前用户隔离。
6. 回答依据面板能显示私人文档来源、文档名、分组、文件名、定位信息和片段；即使模型没有输出合法引用标记，也能显示本次检索到的参考来源并标明是否被回答显式引用。
7. 知识库页面明确说明支持的文件格式和大小限制；不支持、超限、MIME 不匹配、文件头错误、解析失败和索引失败都要给出可理解的提示。

## 2. 非目标与边界

- 不实现分享功能，也不保留“以后再实现”的入口、菜单项或接口。
- 不改变登录、注册、JWT、用户隔离和顶部导航的业务语义。
- 不改变普通模式、ACM 分析、ACM 解题的既有模式定义；只为聊天运行可靠性和知识库范围增加必要字段。
- 不要求后端重启后继续执行已经开始的模型生成任务。若后端重启导致数据库里遗留 `generating` 消息，下一次读取时将其标记为“生成中断/失败”，不伪造继续生成。
- 不新增网页 URL 抓取，不扩大已有文档解析格式范围。

## 3. 当前基线与主要问题

当前聊天页在点击“新建会话”时立即调用 `POST /conversations`，因此会产生没有消息的空会话；会话标题通过双击编辑。聊天流的主要生成逻辑位于 SSE 生成器中，浏览器断开时会影响生成生命周期，导致切换页面后回答可能没有持久化。知识库选择只有空值或单个分组，检索服务无法表达“全部分组”。引用接口只返回切片 ID、片段和定位，没有文档元数据；前端也只在当前页面内存中保存引用。

## 4. 总体架构决策

### 4.1 会话草稿与真实会话

前端维护 `draftConversation` 状态，不给草稿分配数据库 ID，也不调用创建接口。草稿状态可以拥有模式、题目、语言、知识库范围和附件选择，但这些状态只在页面内有效。

发送第一条消息时，前端按以下顺序执行：

1. 使用首条问题生成默认标题（最多 24 个字符，超出使用省略号）。
2. 调用 `POST /conversations` 创建真实会话。
3. 使用返回的会话 ID 启动聊天运行。
4. 只有创建成功并进入运行流程后，左侧列表才加入该会话。

如果用户没有发送问题就切换页面或再次点击“新建会话”，草稿直接丢弃，不产生数据库记录。

### 4.2 会话置顶与批量操作

在 `conversations` 表新增 `pinned` 布尔字段，默认 `false`。列表接口按 `pinned DESC, updated_at DESC` 排序。

保留现有单会话 CRUD，并扩展：

- `PATCH /conversations/{id}`：标题和置顶状态均可单独更新。
- `POST /conversations/bulk`：对当前用户指定的一组会话执行 `pin`、`unpin` 或 `delete`。

所有批量操作都在一次数据库事务中完成，并忽略或拒绝不属于当前用户的 ID，不能产生跨用户副作用。前端多选模式不显示分享入口。

### 4.3 与页面生命周期解耦的聊天运行

不再把模型生成作为 SSE 生成器本身的工作。后端拆成两个层次：

1. **持久化层：** 请求收到后，在事务中保存用户消息和一条 `status=generating` 的助手占位消息。助手消息 ID 作为本次运行 ID；消息增加 `retrieved_chunk_ids` JSON 字段用于恢复检索来源。
2. **进程内运行层：** 使用 `asyncio.create_task` 启动独立生成任务，由 `RunRegistry` 持有任务、停止事件、当前答案、订阅者队列和运行状态。任务只依赖后端进程，不依赖浏览器连接。

初始 `POST /conversations/{id}/messages/stream` 仍返回 SSE，以保持现有调用方式；该接口只负责创建消息、启动任务并订阅任务事件。客户端断开时仅移除订阅者，不取消后台任务。

为刷新和重新进入提供两个接口：

- `GET /conversations/{id}/runs/active`：返回当前会话的活动运行 ID、助手消息 ID、状态和当前已生成内容。
- `GET /conversations/{id}/runs/{run_id}/stream`：发送当前快照，然后订阅后续增量事件；运行结束后发送终态事件并关闭。

运行任务的状态转换为：

```text
generating -> completed
generating -> cancelled
generating -> failed
```

无论前端是否在线，任务结束都必须更新助手消息内容、状态、耗时、首 token 延迟、检索来源和有效引用。用户点击停止时才设置停止事件；切换会话、路由跳转、刷新、退出登录和 SSE 断开都不设置停止事件。

### 4.4 运行事件与重连快照

保留现有事件名称并增加 `run.snapshot`。快照至少包含：

- 运行 ID和助手消息 ID
- 当前内容
- 当前状态
- 当前模式、题目和解题语言
- 已检索的切片 ID和定位
- 已验证的引用（如果生成已完成）

新连接先收到快照，再收到后续 `message.delta`、`citations.validated`、`message.final` 和终态事件。这样用户重新打开页面时可以先看到已有内容，再继续接收剩余内容；如果任务已完成，则快照和数据库消息都能直接恢复最终结果。

运行订阅队列只用于当前后端进程内的实时传输，设置有界长度并在断开时清理。数据库是最终事实来源，进程内状态只负责增量体验。

### 4.5 知识库范围

`ChatRequest` 新增 `knowledge_scope`：

- `none`：不检索知识库，默认值。
- `all`：检索当前用户所有已索引文档。
- `groups`：只检索 `knowledge_group_ids` 指定分组。

为兼容现有客户端，当 `knowledge_scope` 缺省但 `knowledge_group_ids` 非空时，后端按 `groups` 处理；当范围为 `groups` 但没有有效分组 ID 时返回参数错误。

会话附件作为额外的可检索来源：当选择分组和附件时，检索范围是两者的并集；当范围为 `none` 但存在附件时，只检索这些附件。所有分支都附加当前用户、文档未删除、版本状态为 `indexed` 的条件。

检索服务保持全文检索、向量检索和 RRF 合并；`all` 只是不添加分组过滤条件，不绕过用户过滤。

### 4.6 回答依据与引用

助手消息保存本次检索命中的切片 ID列表。新增来源查询接口：

`GET /conversations/{id}/messages/{message_id}/sources`

该接口按当前用户权限返回每个检索来源的：

- `chunk_id`
- 是否被模型输出的合法 `[cite:chunk_id]` 标记引用
- 文档 ID、文档标题、原始文件名、知识库分组名
- 片段内容、相关度、页码/章节/代码行等定位

现有 `.../citations` 接口继续只返回经过引用标记验证的记录，但补充文档元数据。回答依据面板优先展示显式引用；当显式引用为空时展示来源列表并标明“检索到的参考资料”，不把未被模型引用的来源冒充为已引用内容。

模型上下文继续将资料标记为不可信数据，并要求在有依据时输出合法引用。后端仍会删除未知引用标记，只有本次检索结果中的切片才能被保存为有效引用。

### 4.7 上传策略与错误提示

新增 `GET /knowledge/documents/policy` 返回后端实际配置的：

- 支持扩展名
- 最大文件字节数
- 面向用户的格式说明

知识库页面加载该策略，并在选择文件时先做扩展名和大小校验；后端继续执行扩展名、MIME、文件头和大小校验。错误响应统一包含稳定错误码和中文可读消息，至少覆盖：

- `UNSUPPORTED_DOCUMENT_TYPE`
- `DOCUMENT_TOO_LARGE`
- `DOCUMENT_MIME_MISMATCH`
- `INVALID_PDF`
- `INVALID_DOCX`
- `INVALID_HTML`
- `DOCUMENT_PARSE_FAILED`
- `DOCUMENT_INDEX_FAILED`

文档列表显示处理失败的用户可读原因，并保留已有重试操作。

## 5. 数据模型与迁移

新增一个 Alembic revision：

1. `conversations.pinned BOOLEAN NOT NULL DEFAULT FALSE`，添加用户和置顶排序所需索引（如现有数据库策略需要）。
2. `messages.retrieved_chunk_ids JSON NOT NULL DEFAULT '[]'`，只追加字段，不改变已有消息字段语义。
3. 更新 SQLAlchemy 模型、Pydantic 响应和迁移回滚逻辑。

不新增持久化运行表。活动运行由助手占位消息和进程内 `RunRegistry`共同表示；这样可以满足“后端进程仍运行时可恢复”，同时不承诺后端重启续生成。

当读取到 `status=generating` 但进程内没有对应活动运行时，将该消息标记为 `failed`/“生成因后端重启中断”，避免产生永久的假生成状态。

## 6. 前端状态与交互

### 6.1 左侧会话列表

- 列表按后端排序渲染，置顶会话可显示置顶图标。
- 每项右侧显示三个点按钮；点击时阻止触发会话切换，并打开菜单。
- 菜单仅包含重命名、置顶/取消置顶、多选、删除。
- 重命名使用菜单触发的输入框或对话框，不再监听双击。
- 多选模式显示复选框、已选择数量和底部批量置顶/删除操作栏；退出多选后恢复普通列表。
- 删除当前会话后优先切换到下一条可用会话，否则回到临时新对话。

### 6.2 草稿和真实会话

聊天页初始化时如果没有会话，直接显示草稿欢迎态。点击新建只重置草稿和编辑状态。发送首条问题前，输入框、模式、题目、知识库范围和附件仍可正常选择；首条问题提交成功后才加入左侧列表。

### 6.3 生成状态

- 运行状态按会话 ID管理，不再用全局 `busy` 阻塞所有会话。
- 切换会话时只中止当前页面的 SSE 读取，不调用停止接口。
- 进入会话时加载消息；发现 `generating` 助手消息则查询活动运行并订阅重连流。
- 页面卸载、刷新和登出只取消前端订阅，不取消后端任务。
- 当前会话的输入框只在该会话自身有活动运行时禁用。

### 6.4 知识库选择与回答依据

聊天头部使用三类选择：不使用知识库、使用所有知识库、具体分组列表。切换会话或创建新草稿时默认恢复为“不使用知识库”，避免上一个会话的范围意外带入新会话。

回答依据面板在收到检索结果后显示加载态；收到最终消息或重新加载消息后调用来源接口，显示文档级信息和定位。移动端保持现有隐藏/抽屉策略，不改变桌面三栏布局。

## 7. API 变化摘要

### 会话

```text
GET    /conversations
POST   /conversations
PATCH  /conversations/{id}              { title?: string, pinned?: boolean }
DELETE /conversations/{id}
POST   /conversations/bulk              { conversation_ids: UUID[], action: pin|unpin|delete }
GET    /conversations/{id}/runs/active
GET    /conversations/{id}/runs/{run_id}/stream
```

现有 `POST /conversations/{id}/messages/stream` 保留，但内部改为启动独立运行并订阅它；请求体增加 `knowledge_scope`。

### 知识库

```text
GET /knowledge/documents/policy
GET /conversations/{id}/messages/{message_id}/sources
```

现有文档上传、状态、重试、预览、下载和引用接口继续兼容，只增加稳定错误码和来源元数据。

## 8. 错误处理与并发规则

- 同一会话仍只允许一个活动生成；重复发送返回 409，并由前端提示当前会话正在生成。
- 新会话创建与首条消息发送分两次请求；如果创建成功但启动运行失败，用户消息和失败助手消息仍可在会话中重试。
- 任务内部所有异常都要更新助手状态并释放运行锁；SSE 连接异常不能跳过数据库收尾。
- 停止操作是幂等的；任务已经完成时返回当前终态，不删除已保存内容。
- 批量删除、置顶严格按当前用户过滤；部分 ID 不存在时不能影响其他用户数据。
- 检索服务失败时，若用户明确选择了知识库范围，助手消息标记失败并显示检索失败原因；未选择知识库时不调用检索服务。

## 9. 测试与验收

### 后端

- 会话列表置顶排序、重命名、单删、批量置顶、批量删除和跨用户隔离。
- 草稿不产生数据库记录；首问才创建会话和消息。
- 运行任务在 SSE 客户端断开后仍完成并持久化。
- 重新连接运行流时先收到当前快照，再收到后续增量和终态。
- 刷新/重新登录读取到已完成回答；停止只由显式停止请求触发。
- `none`、`all`、`groups` 三种知识库范围及附件并集行为。
- 来源接口返回私人文档元数据，跨用户来源不可读。
- 上传策略、扩展名、大小、MIME、文件头和处理失败错误码。
- 现有认证、消息分页、重试、ACM 模式和知识库处理测试全部回归通过。

### 前端与浏览器

- 新建按钮只显示临时新对话。
- 首问后才出现左侧会话。
- 三个点菜单、重命名、置顶、多选、批量操作和删除后的切换。
- 发送后立即切换会话，原会话回答仍完成。
- 刷新、关闭聊天页后重开、退出登录后重新登录，均能看到完整回答。
- 重新进入生成中的会话显示已有内容并继续接收增量。
- 三种知识库选择默认和切换行为正确。
- 右侧显示私人文档名称、分组、定位和片段。
- 不支持文件、超大文件和后端处理失败都有明确提示。

## 10. 实施顺序

1. 先补充迁移、模型、Schema 和会话 API（置顶、批量、运行状态接口）。
2. 重构后端运行注册表和后台生成任务，先用测试固定断线、重连、停止和持久化行为。
3. 修改前端会话草稿和会话管理交互。
4. 增加知识库范围字段、全部分组检索和来源元数据接口。
5. 修改前端知识库选择、回答依据和上传策略提示。
6. 执行后端回归、前端构建和浏览器验收，最后更新 API/数据模型文档。
