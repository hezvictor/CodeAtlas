# 用户题库归属与管理设计

## 目标

让每个账号拥有一份独立题库：注册时从系统题目模板复制默认题目，之后用户可以对这些默认题目和自己新建的题目进行增加、删除、修改、查询。系统模板只用于新账号初始化，不直接出现在用户题库中。

## 数据与权限

- 保留现有 `problems` 表中的系统模板行：`owner_user_id = NULL`、`source_type = system`。
- 新账号注册时，在同一个数据库事务中复制所有系统模板，写入 `owner_user_id = 新用户 ID`、`source_type = default` 的用户题目。
- 已有账号通过迁移复制系统模板，保证升级后每个账号都有默认题目。
- 题目唯一 ID 继续使用现有 UUID 主键，创建后不可编辑；列表和详情显示完整 UUID，避免短 ID 碰撞。
- 所有题库查询只返回 `owner_user_id = 当前用户 ID`；创建强制写入当前用户 ID；更新、删除和详情查询必须再次校验所有权。
- 删除题目使用硬删除。消息中的 `problem_id` 已设置 `ON DELETE SET NULL`，因此不会破坏历史聊天。

## API

- `GET /problems`：查询当前用户题目，保留关键词、难度、标签和分页筛选。
- `GET /problems/{id}`：查询当前用户题目详情。
- `POST /problems`：创建题目，服务端生成 UUID 和唯一 slug。
- `PATCH /problems/{id}`：更新题目内容，ID 和所有者不可修改。
- `DELETE /problems/{id}`：删除当前用户题目。

创建与更新共用字段：标题、难度、标签、题面、输入描述、输出描述、样例、约束、支持语言。题目标题与文本字段去除首尾空白；标签去重并过滤空值；至少保留一个支持语言。

## 前端体验

- `/problems` 使用题目索引列表替代双列卡片：唯一 ID 在第一列，随后是标题、难度、标签、来源、更新时间和操作。
- 顶部工具栏提供搜索、难度筛选、标签筛选和“新建题目”。列表行提供查看、编辑、删除；删除有二次确认。
- 新建和编辑在当前列表打开右侧抽屉表单，保存后刷新当前列表；不把用户带离题库上下文。
- `/problems/:id` 参考附件的题目详情结构：顶部身份信息和元数据，正文题面，右侧操作区放分析、解题、编辑、删除。
- 现有 ACM 分析和解题入口继续保留。
- 移动端列表变为可换行的两层行布局，操作仍可访问，不依赖 hover。

## Markdown 可行性

可以实现。当前前端已经依赖 `react-markdown` 和 `remark-gfm`，后续可在编辑抽屉内增加左侧 Markdown 源码 `textarea`、右侧 `ReactMarkdown` 实时预览，保存时保留源码。默认不启用原始 HTML；如果未来允许 HTML，需要额外加入 `rehype-sanitize` 做白名单清洗。本次只完成题库归属、CRUD 和详情视觉，不改变现有纯文本字段契约。

## 错误处理与测试

- 访问他人题目和操作系统模板返回 404，不泄露资源存在性。
- 标题、描述、难度、样例和语言字段不合法时返回 422。
- 注册复制失败时整个注册事务回滚，不产生没有默认题目的账号。
- 后端测试覆盖默认题目复制、用户隔离、CRUD 所有权和输入校验；前端通过构建检查并用浏览器验证列表、抽屉、编辑、删除和详情布局。
