# 已确认代码问题的修复设计

## 范围与目标

修复 2026-10-08 当前工作区审查中确认的用户可见问题：个人中心错误响应、改密后的登录状态、首次创建聊天会话失败时的输入保留、Reranker 配置编辑契约、空会话标题，以及临时文件引用校验的高耗时路径。恢复 README 中列出的后端 Ruff 检查。

## 行为契约

1. 个人资料、头像、密码操作只有在 HTTP 成功时才显示成功。失败时保留当前表单或用户状态并显示后端错误。改密成功后清除已失效的本地令牌，引导重新登录。
2. 新会话创建失败时，聊天输入原文仍可编辑和重试；进行中的创建请求不会因重复点击产生多个会话。
3. 已有 Reranker 配置可以仅更新地址或模型名并保留原密钥；新建配置必须提供密钥。保存后的配置仍需通过连接测试才参与检索，页面文案必须说明这一点。
4. 临时资料隐私限制保持原规则：不得持久化文件名、文件 ID 或全文；本次最多引用 500 字符，同一文件在会话中累计最多 10%，连续原文片段从 8 字符起计。先确认受控输入的高耗时在真实请求路径中成立，再优化；不能靠跳过校验或无提示放宽限制。
5. 会话标题在去首尾空白后不能为空。创建和更新接口采用一致校验。
6. Ruff 能通过；跨测试模块导入的 `db` fixture 仍能被 Pytest 正确发现。

## 实施边界

- 不修改 Embedding 失败时的检索策略；现有测试明确要求该行为。
- 不增加数据库迁移、生产环境依赖或新的外部服务。
- 当前工作区有大量既有未提交改动，实施时只暂存本计划对应文件，不重置或覆盖其他改动。
- 数据库和 Redis 集成验证只能使用项目的独立测试环境；本计划文档本身不执行任何业务代码修改。
